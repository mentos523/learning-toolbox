# GEOGRAPHY-DATA 数据表交付说明

## 二、表结构与字段冻结清单

### 2.1 气候类型库 `climateTypes`（G4 判定依据）

- `motto`（冻结口诀，§15 B7）：「以温定带、以水定型」
- `seasonEnum`：`全年多雨 / 夏季多雨 / 冬季多雨 / 全年少雨 / 全年较均匀`（最后一个为增补，已获 GEO-RULING-2026-10-17-07 裁决确认，见§五）
- 每个类型冻结字段：`id / name（类型名） / zone（温度带） / zoneRule（GEO-R14 阈值） / precipRule（降水条件） / season（季节分配） / boundaryNote（边界句）`——改名/增删须经地理专家队书面裁决（B8）。
- `distribution` 为教学辅助字段（非冻结）。
- **类型名来源**：`docs/geography-curriculum.md` dg03.2.2（热带四型）、dg03.2.3（亚热带二型/温带三型/极地拆苔原+冰原二型）、dg09.2.1（高原山地）。
  §十四 B8「地理专家队审定清单」尚未正式发布，本表暂以课程体系类型名为准；审定稿发布后以审定稿为准同步。

12 个类型：热带雨林 / 热带草原 / 热带季风 / 热带沙漠 / 亚热带季风 / 地中海 /
温带海洋性 / 温带季风 / 温带大陆性 / 苔原 / 冰原 / 高原山地气候。

### 2.2 气候站点表 `climateStations`（G4 climate-chart 数据）

- 每个站点冻结字段：`id / name / temp[12]（月均温℃，1 月起） / precip[12]（月降水mm，1 月起） / year（必填，GEO-R16） / dataKind / source / computedZone（口诀直读温度带） / climateTypeId（链接类型库）`。
- 补充字段（非冻结）：`lat / lon / altitude / country / sourceNote / boundaryNote / needsRuling / expectedType / isPlateau`。
- 12 站点逐站对应 12 个类型：新加坡（热带雨林）/ 巴马科（热带草原）/ 孟买（热带季风）/
  迪拜（热带沙漠）/ 武汉（亚热带季风）/ 罗马（地中海）/ 伦敦（温带海洋性）/
  北京（温带季风）/ 乌鲁木齐（温带大陆性）/ 乌特恰维克（巴罗，苔原）/
  阿蒙森-斯科特站（南极点，冰原）/ 拉萨（高原山地）。
- 口诀已知例外在站记录中显性标注：伦敦 `needsRuling: true`（口诀直读亚热带，按分布+成因定温带）；
  拉萨 `isPlateau: true`（口诀直读温带，按 T5「看海拔，口诀之外」定高原山地）。

### 2.3 时区城市表 `timezoneCities`（G6 区时计算题源）

- 冻结字段（B7）：`name / zone（标准时区） / lon（教学用代表经度，东正西负）`。
- 补充字段（非冻结）：`country / note`。
- 口径：标准时区，不计夏令时；整小时教学口径（新德里 UTC+5:30 非整小时未入库）。
- 14 城：北京（+8）/ 东京（+9）/ 曼谷（+7）/ 悉尼（+10）/ 惠灵顿（+12）/ 苏瓦（+12）/
  檀香山（-10）/ 洛杉矶（-8）/ 墨西哥城（-6）/ 纽约（-5）/ 里约热内卢（-3）/
  伦敦（0）/ 开罗（+2）/ 莫斯科（+3）。东半球 9 城、西半球 5 城；
  跨 180° 经线案例：苏瓦/惠灵顿（东十二区）↔ 檀香山/洛杉矶（西十区/西八区），分居日界线两侧。
- 已用 UTC 验算的工作示例（G6 四步法）：已知洛杉矶 10 月 17 日 10:00（西八区），求苏瓦（东十二区）：
  ①定时区：-8 / +12；②定东西：+12 > -8，苏瓦在东；③加减：时区差 20，东加 → 10:00 + 20h = 次日 06:00；
  ④看日期：10 月 18 日 06:00；⚠ 跨 180° 经线提示（分居日界线两侧）。
  UTC 校验：洛杉矶 10/17 10:00（-8）= 10/17 18:00 UTC → 苏瓦（+12）= 10/18 06:00 ✓。

### 2.4 图层 schema `layerSchema`（G12 layer-stack）

- 冻结字段（B12）：`id / name / kind / visible / dataRef`。
- `kindEnum` 冻结（G12 spec 逐字）：`terrain 地形 / climate 气候 / river 河流 / pop 人口 / traffic 交通 / industry 产业`。
- 冻结限额：`maxVisible = 3`（同时可见 ≤ 3 层）；`maxLayersPerRegion = 6`（单区域 ≤ 6 层）。
- `dataRef` 约定：「区域 id:图层数据 id」字符串，指向构建时内嵌的图层数据键（本表只冻结字段名）。
- 区域示例：`qlhuai` 秦岭—淮河线两侧（六层预设：1 月 0℃ 等温线 / 800mm 年等降水量线 / 温度带界线 /
  干湿区界线 / 水田旱地 / 水稻小麦，默认只开两层）；`wuhan` 武汉及长江中游（「一城讲全书」案例区，
  图层待后续批次供数；附 G12 thoughtExp 示例：关掉河流层还能判断武汉在哪吗）。

## 六、更新纪律

1. **数值只认来源**：任何温度/降水/时区数值的修改，必须注明来源与年份，走「黄队配表 → 地理专家队核验 → 蓝队入库」流程；无可靠来源不编造，标「待补」。
2. **口径冻结**：GEO-R14 阈值、类型名、图层冻结字段、时区冻结字段的变更 = 口径变更，须地理专家队书面裁决，不得自行调整。
3. **年份必填**：新增站点必须带 `year`（GEO-R16）；统计值必须注年份 + 来源（GEO-R52）；多年平均值按 GEO-R54 诚实表述（用「约」）。
4. **例外显性化**：口诀例外（如伦敦、拉萨）必须在 `boundaryNote` / `needsRuling` 中写明，不得静默入库。
5. **只写文件、不提交**：本批数据表不 commit、不 push、不升版号；`dataVersion` 为数据表自身溯源码，非仓库版号。
6. **文件域隔离**：严禁触碰 `modules/biology/`、`docs/biology-curriculum.md`、`assets/js/registry.js`（注册表接线待后续批次，地理队统一处理）。
7. **待补清单驱动**：§四清单逐项关闭后更新本 README；二级来源替换为官方值时同步更新 `source` / `dataKind` / `year`。
