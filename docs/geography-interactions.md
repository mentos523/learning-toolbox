### 0.2 地理专属色板映射 `--geog-*`

地理**不另起色板**：定义 `--geog-*` 语义变量，值全部别名 `--geo-*`（浅色/深色两套色值自动跟随几何的深色切换，无需另写深色值）。变量名避开几何在用的 `--geo-*`，用 `--geog-*`（curriculum 口径）。

```css
:root {
--geog-known: var(--geo-known); /* 已知量：蓝 —— 已知地时间、已知比例尺、已知坐标 */
--geog-target: var(--geo-target); /* 待求量：朱红 —— 待求区时、待找地点、判读目标（加粗） */
--geog-graticule: var(--geo-grid); /* 经纬网线：常规网格色 */
--geog-equator: var(--geo-corr-a); /* 赤道/特殊纬线：橙 + 文字标注（"赤道 0°"） */
--geog-meridian0: var(--geo-corr-b); /* 本初子午线/特殊经线：天蓝 + 文字标注（"0°"） */
--geog-contour: var(--geo-line); /* 等高线：常规描边色 + 高程注记文字（双编码） */
--geog-contour-hi: var(--geo-corr-a);/* 凸向判读高亮（山脊/山谷判定态）：橙 + 口诀文字 */
--geog-temp: var(--geo-target); /* 气温曲线：朱红 + "气温"图例文字 */
--geog-precip: var(--geo-known); /* 降水柱状：蓝 + "降水"图例文字 */
--geog-warm: var(--geo-target); /* 暖流：朱红 + 箭头 + "暖流"文字 */
--geog-cold: var(--geo-known); /* 寒流：蓝 + 箭头 + "寒流"文字 */
--geog-high-p: var(--geo-target); /* 高压 H：朱红 + "H"字母（图例注明"颜色表气压高低，不表冷暖"） */
--geog-low-p: var(--geo-known); /* 低压 L：蓝 + "L"字母（同上，与温度色系脱钩） */
--geog-plate-a: var(--geo-corr-c); /* 板块色组：蓝绿/橙/天蓝/朱红/灰系，六大板块各一色 + 板块名文字 */
--geog-pop-dense: var(--geo-target); /* 人口密度高：朱红系 + 分级数值图例 */
--geog-pop-sparse: var(--geo-highlight); /* 人口密度低：黄系 + 分级数值图例 */
--geog-correct: var(--geo-corr-c); /* 判读正确：蓝绿 + "✓"文字 */
--geog-wrong: var(--geo-target); /* 判读错误：朱红 + "✗"文字（纠正用，不做惩罚） */
--geog-highlight: var(--geo-highlight); /* 高亮闪烁：黄（配深色字） */
--geog-day: var(--geo-highlight);/* 昼半球：黄系 + "昼"文字（G2 晨昏线） */
--geog-night: var(--geo-aux); /* 夜半球：灰系 + "夜"文字（G2 晨昏线） */
}
```

映射问答（pedagogy 第八章颜色编码约定的变量落点）：

- **地形分层设色 = ？** 绿（平原）→ 黄（高原）→ 褐（山地）为"海拔密码"，是地理学科事实颜色，按 pedagogy 第八章渲染（**不套用 `--geog-*` 抽象**，因这是教材约定色；v1.1 已删除 `--geog-relief-low/mid/hi` 三变量）；但旁边必须配"海拔密码"图例 + 海拔分级文字（"低/中/高"），**绝不只靠颜色**（色盲 + 深色模式；深色下白队按 W-G9 验收可辨性）。
- **暖流/寒流 = ？** `--geog-warm`（朱红）/ `--geog-cold`（蓝），箭头方向 + "暖流"/"寒流"文字三编码。
- **高压 H/低压 L = ？** `--geog-high-p`/`--geog-low-p` + "H"/"L" 字母；**图例必须注明"颜色表气压高低，不表冷暖"**（pedagogy 第八章：红色高压易被误读为"热"，约定与温度色系脱钩）。
- **六大板块 = ？** 亚欧/非洲/印度洋/太平洋/美洲/南极洲六色定版（dg02.2.2），每块配板块名文字 + 边界线加粗（双编码）。
- **判读正误 = ？** `--geog-correct`（蓝绿 + ✓）/ `--geog-wrong`（朱红 + ✗）；答错只做"即时纠正"（切 3D/给口诀），**不做扣分、不记错题本惩罚**（沿用物理 Y1"不判对错"精神，地理闯关是练习不是考试）。
- **已知/待求 = ？** 沿用物理全局约定：已知蓝、待求朱红（区时计算、比例尺换算页）。
- **昼/夜 = ？** `--geog-day`（黄 + "昼"）/ `--geog-night`（灰 + "夜"），G2 晨昏线专用。

### 0.3 全局铁律（地理页同样执行）

1. `params` 里**不出现具体色值**，只用 `--geog-*` 语义名；深色模式自动切换（别名机制，渲染器不重绘画布）。
2. **逻辑单位 0–100**（y 向上），不写死 px；触摸手柄半径 ≥ 6 逻辑单位（≈44px @ 390px 画布），热区再外扩 50%。
3. 反馈走 M6：吸附/落定/状态切换**视觉必选**（flash/ripple），`navigator.vibrate` 与合成音效为可选加分项。
4. 双编码：方向 = 颜色 + 箭头/文字；高低 = 颜色 + 注记文字；正误 = 颜色 + ✓/✗；昼夜 = 颜色 + "昼/夜"文字，**绝不只靠颜色**。
5. 读数行一律走 MathML（经纬度符号 °/N/S/E/W、℃、mm、km、h），单位与数值同行，不许裸文本；经纬度书写规范**先纬后经**（如 40°N, 116°E）。
6. 讲解页口径沿用几何：`pageKind: "explain"` + 全页 ≤300 字 + 点拨区 36vh 内滚动；交互页 ≤150 字；exploreTip ≤ 40 字只说"动手做什么"不说结论。
7. **地图诚实铁律**（地理特有，见 pedagogy 第九章）：
- 每张真图必带三要素条（方向｜比例尺｜图例），`params.mapFrame` 可配；缺一项即不合格。
- 所有"示意"类页面（地球仪示意、虚拟地形、简化轮廓）必须常驻"**示意**"声明 + "非精确比例"小字；不许拿示意图当真图查距离。
- 世界地图页必须可配投影名称 + 变形声明小字（`params.projection`）。
- 地形剖面图必须标注"垂直夸大 ×N 倍（示意）"。
- 人口/经济数据必须注年份；不确定的数字写"约"。
8. **国界/领土口径**（硬约束）：交互组件只做"能力"（图层开关、点选、着色），**不预置任何争议表述**；凡涉国界/行政区划的底图，以地理专家队审定为准，黄队不自绘、蓝队不"艺术加工"；争议处标"示意"。组件 params 里**不出现**国界走向、领土归属判断类字段。

## G1 · globe-spin（可旋转经纬网地球仪）

拖拽旋转的示意地球仪；经纬线开关；点击球面任意点读数徽章实时显示经纬度（先纬后经）；
"找一找"模式：给出经纬度，学生在球上点选（容差 ±5°）。
适用课型：**dg01.2.1–2.4 经纬网**（跃升 1 立靶页）；**dg02.1.1 七大洲**（大洲定位）；**dg06.2.3 南极洲**（极点视角）。

### Schema

| 参数 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| `mode` | string | — | `"explore"` | `"explore"`（自由旋转 + 点读坐标）/ `"find"`（找一找闯关：按 `targets` 点选） |
| `targets` | array | — | — | `mode:"find"` 时必填：每项 `{name（如"北京"), lat（如 40), lon（如 116)}`；经纬度为度数（东经/北纬为正） |
| `graticuleStep` | number | — | `30` | 经纬网间隔（度，15/30 二选一） |
| `showGraticule` | boolean | — | `true` | 经纬线开关（可配初始态） |
| `showLabels` | boolean | — | `true` | 赤道/本初子午线/回归线/极圈文字标注开关 |
| `polarView` | boolean | — | `false` | 是否提供极点视角切换按钮（北极/南极俯视：经线汇聚、纬线变同心圆） |
| `tolerance` | number | — | `5` | `mode:"find"` 点选容差（度，见 §15 B6） |
| `spinHint` | boolean | — | `true` | 初始是否显示"拖一拖，转地球"手势提示（3 秒后自动消失） |
| `landStyle` | string | — | `"schematic"` | 固定 `"schematic"`：陆地为示意色块（**不画国界线**，国界口径见 §0.3 第 8 条）；"示意"声明常驻 |

- 渲染：2D Canvas 正射投影示意地球（**不是真实纹理贴图**，零二进制资源）；拖拽旋转（惯性缓动 ≤600ms）；
点击球面 → 经纬度反算 → 读数徽章（MathML，如 `40°N, 116°E`，**先纬后经**）。
- 经线指示南北、纬线指示东西：点读时徽章附一行小字"经线指示南北 · 纬线指示东西"（审计清单第 1 条回填位，黄队可配 `hintLine`）。
- 极点视角：北极俯视配自转方向箭头（逆时针）+ "北逆南顺"文字；此视角下东西方向判读按自转方向（防"地图右边"陷阱）。
- `landStyle` 冻结为 `"schematic"`：陆地轮廓为简化示意色块，**不绘制国界/行政区划线**（国界口径硬约束）；大陆名文字标注可配（`labels:["亚洲","非洲",…]`，地理专家队审定译名）。

### 示例

```js
interaction: {
type: "globe-spin",
params: {
mode: "find",
targets: [
{ name: "北京", lat: 40, lon: 116},
{ name: "开罗", lat: 30, lon: 31}
],
graticuleStep: 30, showGraticule: true, showLabels: true,
polarView: true, tolerance: 5, spinHint: true, landStyle: "schematic"
}
}
```

### 输入 / 输出

- 输入：手指/鼠标拖拽旋转；点球面读坐标；`find` 模式点选目标（容差 ±5° 内算找对）。
- 输出：读数徽章实时经纬度（MathML，先纬后经）；找对 → "✓ 找对了" + M6 flash；找错 → "再转转，从经纬网想想"（不判错、不扣分）。

### 触控要求

- 旋转拖拽：整球为热区；点选热区：球面点 ≥ 44px 等效（球面投影点热区外扩）；
- 极点视角切换按钮 ≥ 44px；经纬线开关 ≥ 44px。

### 深色模式

- 球体 `--geog-night` 暗面 / 昼面示意色深色自动跟随；经纬网 `--geog-graticule`；
- 赤道 `--geog-equator`、本初子午线 `--geog-meridian0` 深色提亮 + 文字标注。

### 双编码

- 坐标：数字 + °/N/S/E/W 符号文字（灰度可辨）；赤道/回归线/极圈：颜色 + 文字标注（"赤道 0°"）；
- 找对/找错：✓/文字，不只靠颜色。

### 复用几何

- 拖拽旋转手柄机制复用 `vertex-drag`（可拖顶点 ≈ 可拖球面）；
- 点选热区复用 `tap-highlight`；`find` 模式判对徽章复用 `ratio-slider` 不变量徽章范式。

### 黄队接口（先动手后结论）

- 动手：拖地球转一圈，指着武汉问"它在哪" → 现象：读数徽章 `30°N, 114°E`（先纬后经） → 结论点题："经纬网是地球的'地址'——先报纬度（南北），再报经度（东西）"。
- 动手：切北极俯视，看经线 → 现象：经线都汇到一点、纬线变成一圈圈 → 结论："极点处，'东/西/南/北'要按自转方向重新想——地图的右边会骗人"（审计清单第 1 条）。

### 蓝队评审

- ✅ **可实现**：原生 JS + Canvas 2D 正射投影（经纬度↔屏幕坐标解析式），零依赖；陆地示意色块为简化多边形路径（构建时内嵌，见 §15 B3）。
- 离线预计算：陆地示意轮廓路径点（构建时生成，运行时零外部依赖）。
- 性能红线：旋转 rAF 逐帧重绘，路径点 ≤ 2000；低端机降 `graticuleStep` 到 30 固定、关惯性缓动（渲染器内部处理，不暴露 params）。

### 常见坑

1. **`landStyle` 冻结 `"schematic"`**：不许配真实卫星纹理（零二进制资源铁律）；不许画国界线（国界口径硬约束）。
2. **"示意"声明常驻**：角落小字"示意｜非精确比例"不可关（W-G8）。
3. **先纬后经**：读数徽章永远 `纬度, 经度` 顺序；`targets` 里写反（lon 当 lat）要在校验清单拦（见附校验清单第 7 条）。
4. **极点视角的方向箭头**：北极逆时针、南极顺时针，箭头方向禁反（审计清单第 1 条"北逆南顺"）。

## G2 · terminator-sim（晨昏线与昼夜模拟）

地球自转动画 + 晨昏线叠加；拖"时间"滑块看晨昏线"扫"过（天亮/天黑）；拖"日期"滑块看晨昏线倾斜变化（二分二至）；
点不同纬度显示昼夜长短读数（极昼/极夜标注）。
适用课型：**dg14.2.1–2.3 地球运动**（跃升 4 立靶页）；**dg01.2.4 方向判读**（昼夜交替回填）。

### Schema

| 参数 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| `time` | object | — | `{min:0,max:24,step:1,init:12}` | 时间滑块（小时，0–24；对应晨昏线位置） |
| `date` | object | — | `{min:1,max:365,step:15,init:80}` | 日期滑块（年积日；二分二至附近自动吸附提示，黄队配 `solsticeMarks`） |
| `latitude` | object | — | `{min:-66.5,max:66.5,step:5,init:30}` | 观察纬度滑块（度；点选"看某纬度的昼夜长短"） |
| `showTerminator` | boolean | — | `true` | 晨昏线开关（晨昏线 = 昼夜分界线，文字常驻） |
| `cityMark` | object | — | — | 城市标记（如 `{name:"武汉", lat:30, lon:114}`）；晨昏线扫过时 flash + "武汉天亮了/天黑了" |
| `spinSpeed` | number | — | 冻结 | 动画速度内部归一化（标注"示意，非真实速度"常驻，不暴露 params） |

- 昼夜长短计算：解析式（太阳赤纬 δ 按日期算，cos H = −tanφ·tanδ）；读数行（MathML）：`昼长 = … 小时` + 极昼/极夜徽章（"极昼"/"极夜"文字 + `--geog-day`/`--geog-night`）。
- 晨昏线倾斜：二分日晨昏线与经线重合（与地轴垂直），二至日倾斜 23.5°；日期滑块拨动时倾斜实时变 + 小字"倾斜因地轴倾斜"。
- `cityMark` 扫过事件：晨昏线经过该经度时 flash + 文字（"武汉天亮了"），配 M6 可选音效。

### 示例

```js
interaction: {
type: "terminator-sim",
params: {
time: { min: 0, max: 24, step: 1, init: 12},
date: { min: 1, max: 365, step: 15, init: 172},
latitude: { min: -66.5, max: 66.5, step: 5, init: 30},
showTerminator: true,
cityMark: { name: "武汉", lat: 30, lon: 114}
}
}
```

### 输入 / 输出

- 输入：时间滑块 / 日期滑块 / 纬度滑块。
- 输出：晨昏线扫动动画 + 昼长读数 + 极昼/极夜徽章 + 城市天亮/天黑事件。

### 触控要求

- 三个滑块轨道 ≥ 44px 高；晨昏线只读（不可拖）；
- 日期滑块在二分二至处有刻度吸附提示（"春分""夏至"文字）。

### 深色模式

- 昼半球 `--geog-day`、夜半球 `--geog-night`、晨昏线 `--geog-highlight` 黄粗线 + "晨昏线"文字；
- 深色下昼夜对比 ≥ 3:1（W-G9 抽查）。

### 双编码

- 昼夜：颜色 + "昼"/"夜"文字；晨昏线：黄粗线 + "晨昏线（昼夜分界线）"文字；
- 极昼/极夜：文字徽章 + 昼长读数（"24 小时"/"0 小时"）。

### 复用几何

- 滑块范式复用代数 `slider-lab`；"示意，非真实速度"标注复用化学 C7 动画角小字约定。

### 黄队接口（先动手后结论）

- 动手：拖时间滑块从 0 到 24 → 现象：晨昏线扫过武汉，"天亮了"→"天黑了" → 结论点题："转一圈是一天——亮的那半是白天，暗的那半是黑夜，晨昏线是昼夜的分界线"。
- 动手：日期拨到夏至（172 天），纬度拨到 66.5°N → 现象：昼长 24 小时、"极昼"徽章 → 结论："夏至北极圈里整天不黑——地轴歪着，太阳照得到极点"。

### 蓝队评审

- ✅ **可实现**：昼长解析式 + Canvas 2D 昼夜明暗渲染，零依赖；晨昏线为大圆投影曲线（解析式）。
- ⚠️ **降级可实现**：不做真实大气散射/曙暮光渐变（⬇ 主动降级（教学聚焦）：昼夜交界画一条清晰晨昏线，不做曙光带渐变；真实理由：初中教学目标是"昼夜分界 + 昼长变化"，曙暮光分级属高中拓展，零依赖实现 ROI 为负）。
- 性能红线：无（单帧重绘）。

### 常见坑

1. **"示意，非真实速度"常驻**：动画角小字不可关（pedagogy 9.1 虚拟地形行）。
2. **"窗帘边"类比禁用**：晨昏线文案只用"昼夜的分界线"，不许用"窗帘边"（pedagogy T7：怕暗示线是固定的——线是动的！）。
3. **极昼/极夜徽章必须配昼长数字**：只写"极昼"不给"昼长 24 小时"是半成品（W-G4 类比）。
4. **日期滑块吸附文案**：二分二至刻度文字由黄队配（"春分/夏至/秋分/冬至"），蓝队只做吸附位。

## G3 · contour-3d（等高线 ↔ 3D 地形联动）

等高线地形图 ↔ 3D 地形（示意山体）左右联动：拖"水位"滑块看等高线一条条"长"出来；
山脊/山谷/鞍部/陡崖/山顶点选判读闯关；答错即时切 3D 视角纠正（"看，水往哪流"）。
适用课型：**dg01.3.3 等高线地形图**（跃升 2 立靶页，红线辨析①）；**dg09.3.2 长江**（红线①回填：河流流向与等高线凸向相反）。

### Schema

| 参数 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| `terrain` | string | ✅ | — | 地形模板枚举：`"hill"`（单山体）/ `"ridge-valley"`（山脊+山谷）/ `"saddle"`（鞍部双峰）/ `"cliff"`（陡崖） |
| `contourInterval` | number | ✅ | — | 等高距（米，如 100；滑块步进单位，黄队配） |
| `waterLevel` | object | — | `{min:0,max:500,step:50,init:0}` | "水位"滑块（米）：水位上升淹没低处，等高线逐条显现（"长"出来） |
| `quiz` | array | — | — | 判读闯关：每项 `{id, kind:"ridge"/"valley"/"saddle"/"cliff"/"peak", prompt}`；学生点选图上位置判读 |
| `show3D` | boolean | — | `true` | 是否显示 3D 联动视图（`false` 时为纯等高线判读模式） |
| `verticalExaggeration` | number | — | `2` | 垂直夸大倍数（3D 视图角落常驻"垂直夸大 ×2（示意）"，见 pedagogy 9.1） |
| `motto` | string | — | 冻结 | 口诀冻结为"**凸高为谷、凸低为脊**"（与红线①逐字一致，见 §15 B7；黄队不可改写） |

- 联动：等高线图上 hover/点选某条等高线 → 3D 地形上对应高度环带高亮（`--geog-contour-hi`）；
3D 上点山脊/山谷 → 等高线图上对应凸起部位闪烁 + 口诀浮现。
- 闯关纠正：答错 → 自动切 3D 视角 + 箭头示意水流方向（"看，水往哪流——水往低处流，河流在山谷里"）→ 再答一次（不扣分）。
- 陡崖模板：等高线重合处配文字"等高线重合 = 陡崖（楼层叠在一起）"（pedagogy T2 边界句）。

### 示例

```js
interaction: {
type: "contour-3d",
params: {
terrain: "ridge-valley",
contourInterval: 100,
waterLevel: { min: 0, max: 500, step: 50, init: 0},
quiz: [
{ id: "q1", kind: "valley", prompt: "点一点：山谷在哪里？（想想水往哪流）"},
{ id: "q2", kind: "ridge", prompt: "点一点：山脊在哪里？"}
],
show3D: true, verticalExaggeration: 2
}
}
```

### 输入 / 输出

- 输入：水位滑块 / 点选等高线 / 3D 旋转（示意山体可转）/ 闯关点选。
- 输出：等高线逐条显现 + 3D 联动高亮 + 判读 ✓/✗ + 答错即时 3D 纠正。

### 触控要求

- 水位滑块 ≥ 44px；等高线点选热区：线宽热区 ≥ 44px（透明加粗描边）；
- 闯关点选热区 ≥ 44px（目标部位外扩）。

### 深色模式

- 等高线 `--geog-contour`（深色近白）+ 高程注记文字；联动高亮 `--geog-contour-hi`；
- 3D 地形分层设色深色可辨（W-G9）。

### 双编码

- 等高线：线 + 高程注记数字（"200m"）；山脊/山谷：颜色 + 口诀文字（"凸高为谷、凸低为脊"）+ 水流箭头；
- 判读正误：✓/✗ + 文字，不只靠颜色。

### 复用几何

- 滑块范式复用代数 `slider-lab`；3D 示意山体渲染复用化学 C7 关键帧/投影思路（本交互为静态地形，无需粒子引擎）；
- 闯关点选复用 `tap-highlight`。

### 黄队接口（先动手后结论）

- 动手：拖水位滑块从 0 往上涨 → 现象：等高线一条条"长"出来，先出来的是低处 → 结论点题："等高线是'等高楼的楼层线'——同一条线上，海拔一样高"。
- 动手：闯关点山谷点错 → 现象：切 3D，水往低处流的箭头 → 结论："凸高为谷、凸低为脊——先问水往哪流，再判读"（红线①立靶）。

### 蓝队评审

- ⚠️ **降级可实现**：原生 JS + Canvas 2D（等高线图）+ Canvas 2.5D 示意山体（高度场渲染，**非 WebGL**）；
地形为参数化模板（`terrain` 四种），**不做真实 DEM 数据加载**（⬇ 主动降级（教学聚焦）：
真实 DEM（如某山真实高程）零依赖/file:// 下体积与加载 ROI 为负；教学目标是"等高线↔地形对应关系"，参数化模板已达成）。
- 离线预计算：四种地形模板的等高线路径（构建时生成）。
- 性能红线：3D 示意山体逐帧旋转 ≤ 60fps；低端机降 3D 分辨率（渲染器内部处理）。

### 常见坑

1. **口诀逐字冻结**："凸高为谷、凸低为脊"（见 §15 B7）；页内任何改写（如"凸向高处是山谷"）= 不通过（W-G2）。
2. **"垂直夸大 ×N（示意）"常驻**：3D 角落小字不可关（pedagogy 9.1 地形夸张行）。
3. **陡崖处等高线重合必须配文**："楼层叠在一起"边界句（pedagogy T2），否则学生以为画错了。
4. **答错不扣分**：闯关是练习，纠正即时但无惩罚（沿用 Y1 精神）。

## G4 · climate-chart（气候资料图判读器）

气温曲线（红）+ 降水柱状（蓝）双变量同读；两步向导**强制顺序**：①"以温定带"（点读最冷月均温 → 温度带徽章）→
②"以水定型"（点读年降水总量 + 季节分配 → 类型徽章）；判读结果与气候类型库联动。
适用课型：**dg03.2.4 气候资料图判读**（跃升 6 立靶页，红线辨析③）；**dg06.1.2 亚洲 / dg06.2.1 非洲**
（气候判定实战回填）；**dg09.2.1 中国的气候**（季风回填）。

### Schema

| 参数 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| `stations` | array | ✅ | — | 气候站点：每项 `{name（如"武汉"), temp:[12 个月均温 ℃], precip:[12 个月降水 mm], year（如 2020)}`；`year` 必填（数据年份，审计清单第 10 条） |
| `mode` | string | — | `"guided"` | `"guided"`（两步向导，顺序强制）/ `"free"`（自由判读：两步可跳，但顺序错时提示） |
| `stepOrder` | string | — | 冻结 | 冻结 `"temp-first"`：先以温定带、再以水定型（红线③，见 §15 B8；不可配反） |
| `climateLib` | string | — | `"内置"` | 气候类型库引用（地理专家队审定清单，见 §15 B8；params 只传引用名，不内嵌判定规则） |
| `compareMode` | boolean | — | `false` | 是否开三地对比模式（如武汉/北京/广州三资料图并排，`stations` ≥ 3 时可用） |

- 两步向导：① 点气温曲线最低点 → 读数 `最冷月均温 = … ℃` → 徽章"温度带：亚热带"（阈值：>15℃ 热带 / 0–15℃ 亚热带 / 最冷月<0℃ 温带 / 最热月<10℃ 寒带，curriculum 红线③）；
② 点降水柱 → 读数 `年降水 = … mm` + 季节分配形态（"夏季多雨"/"冬季多雨"/"全年多雨"/"全年少雨"四选一按钮）→ 徽章"类型：亚热带季风气候"。
- 顺序强制：`mode:"guided"` 时第②步锁定，不完成第①步不能进（灰化 + 提示"先定带，再定型"）；`mode:"free"` 时允许跳步，但判读提交时若顺序反了，提示"红线③：先看温度带"（不判错）。
- 坐标轴诚实：横轴月份、纵轴 ℃/mm 双轴，图例"红=气温、蓝=降水"常驻（pedagogy 第八章）。

### 示例

```js
interaction: {
type: "climate-chart",
params: {
stations: [
{ name: "武汉", temp: [4,6,11,17,22,26,29,28,24,18,12,6], precip: [45,60,90,130,170,220,190,120,80,70,50,35], year: 2020},
{ name: "北京", temp: [-3,0,8,15,21,26,28,26,21,14,6,-1], precip: [3,5,10,20,35,80,180,160,50,20,8,3], year: 2020}
],
mode: "guided", compareMode: true, climateLib: "内置"
}
}
```

### 输入 / 输出

- 输入：点气温曲线最低点 / 点降水柱 / 季节分配四选一 / 站点切换。
- 输出：两步徽章（温度带 → 气候类型）+ 读数行（MathML，℃/mm 同行）+ 类型库联动说明。

### 触控要求

- 曲线/柱点选热区 ≥ 44px（数据点外扩）；季节分配四选一按钮 ≥ 44px；
- 三地对比模式下每图 ≥ 44px 点选区，390px 下纵向排布（不横向挤压）。

### 深色模式

- 气温曲线 `--geog-temp`、降水柱 `--geog-precip` 深色提亮；坐标轴 `--geo-grid`；
- 徽章文字走 `--geo-text`（对比度 ≥ 4.5:1）。

### 双编码

- 气温/降水：颜色（红/蓝）+ 图例文字 + 曲线/柱状形态；
- 两步：数字徽章"①/②" + "以温定带/以水定型"文字 + 阈值文字（">15℃ 热带"）。

### 复用几何

- 曲线描点复用代数 `plot-points`；两步向导复用化学 Y12 `stoich-steps` 的分步范式（`free` 模式的顺序提示 ≈ 查表校验）；
- 图像点读可叠加物理 Y4 `graph-reader`（读最冷月均温即"读极值"）。

### 黄队接口（先动手后结论）

- 动手：点武汉气温曲线最低点 → 现象：`最冷月均温 = 4℃` → 徽章"亚热带" → 动手点降水柱 → 现象：`年降水 ≈ 1290mm`、夏季多雨 → 徽章"亚热带季风气候" → 结论点题："以温定带、以水定型——先看脸的冷暖，再看表情的干湿"（红线③立靶）。
- 对比动手：切北京 → 现象：最冷月 −3℃ → 温带 → 结论："同样是季风，北京是温带季风——定带这一步，决定了后半句"。

### 蓝队评审

- ✅ **可实现**：原生 JS + SVG/Canvas + MathML，零依赖；判定逻辑为阈值查表（地理专家队审定，见 §15 B8），纯前端。
- 离线预计算：无（站点数据构建时内嵌）。
- 性能红线：无。

### 常见坑

1. **顺序不可反**：`stepOrder` 冻结 `"temp-first"`；任何"先看降水"的变体 = 不通过（W-G4，红线③）。
2. **数据必须注年份**：`stations[].year` 必填，缺失校验不通过（审计清单第 10 条；W-G7）。
3. **高原山地气候边界**：口诀不覆盖高原山地气候——判读结果为高原/山地站点时，徽章配边界句"高原山地气候看海拔，口诀之外"（pedagogy T5）。
4. **"约"字诚实**：年降水读数写"约 1290mm"（站点多年平均的估算性质，审计清单第 7 条）。

## G5 · wind-current（风带洋流拖拽）

## G6 · timezone-calc（区时计算练习器）

世界时区盘（24 时区可点选）：输入已知地时间 → 点选目标城市 → 自动显示"目标在东/西"方向箭头；
分步展示：①定时区 → ②定东西 → ③加减小时 → ④看日期；跨日界线时日期 ±1 天高亮警示。
适用课型：**dg14.2.4 区时与地方时**（跃升 5 立靶页，红线辨析②）；**dg15.2.2 交通运输**（航班时刻换算回填）。

### Schema

| 参数 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| `cities` | array | ✅ | — | 城市表：每项 `{name（如"北京"), zone（时区，如 8), lon（如 116)}`；黄队配 12–16 个（见 §15 B7） |
| `knownCity` | string | ✅ | — | 已知地（`cities` 中的 name） |
| `knownTime` | object | ✅ | — | 已知时间 `{hour, minute}`（24 小时制） |
| `steps` | array | — | 冻结四步 | 分步展示：`["定时区","定东西","加减小时","看日期"]`（冻结顺序，见 §15 B7；复用化学 Y12 分步范式） |
| `dateLineAlert` | boolean | — | `true` | 跨 180° 经线时日期 ±1 天高亮警示（默认 true，不可关闭） |
| `directionRule` | string | — | 冻结 | 方向基准冻结文案："东加西减的'东'指东经度增大方向（地球自转方向），不是地图右边"（红线②，见 §15 B7） |
| `mode` | string | — | `"zonetime"` | 预留：高中扩展 `"localtime"`（地方时按经度差 15°=1h 精确到分，dg14.2.4 严格化页），本版不启用 |

- 定东西：比较两地经度，沿"经度增大方向"（自转方向）判定目标在已知地的东/西；方向箭头画在时区盘上（弧形箭头 + "东"/"西"文字），**不以屏幕左右为准**。
- 加减：时区差 = |zone 差| 小时；"东加西减"（目标在东则加）；地方时模式（`mode` 扩展预留，高中版按经度差 15°=1h，初中默认区时整小时）。
- 看日期：跨日界线（经度跨越 ±180°）→ 日期 −1/+1 天，高亮警示条（"--geog-wrong` 底 + ⚠ + 文字"日期减一天/加一天"）。
- "北京时间"特别注：页内一句"北京时间 = 东八区区时，不是北京的地方时"（审计清单第 4 条）。

### 示例

```js
interaction: {
type: "timezone-calc",
params: {
cities: [
{ name: "北京", zone: 8, lon: 116},
{ name: "东京", zone: 9, lon: 140},
{ name: "伦敦", zone: 0, lon: 0},
{ name: "纽约", zone: -5, lon: -74}
],
knownCity: "北京",
knownTime: { hour: 20, minute: 0},
dateLineAlert: true
}
}
```

### 输入 / 输出

- 输入：输入已知时间 / 点选目标城市。
- 输出：四步分步展示（时区 → 东西箭头 → 加减 → 日期）+ 目标时间读数（MathML，`20:00 + 1h = 21:00`）+ 跨日界线警示。

### 触控要求

- 时区盘点选热区 ≥ 44px（24 时区扇形，390px 下配城市列表备选点选）；
- 时间输入框 ≥ 44px 高（`inputmode="numeric"`）。

### 深色模式

- 时区盘 `--geog-graticule` 网格；已知地 `--geog-known`、目标地 `--geog-target` + 文字；
- 方向箭头 `--geog-highlight` + "东/西"文字。

### 双编码

- 东西方向：弧形箭头 + "东"/"西"文字（不以屏幕左右为准）；
- 加减：`+`/`−` 符号 + "东加西减"文字；日期警示：⚠ + 文字。

### 复用几何

- 分步展示复用化学 Y12 `stoich-steps` 分步范式（一步一核对）；
- 时区盘点选复用 `tap-highlight`。

### 黄队接口（先动手后结论）

- 动手：已知北京 20:00，点东京 → 现象：四步走完，"东京在北京东边，加 1 小时，21:00" → 结论点题："东加西减——加还是减，看目标在已知地的东边还是西边，基准是两地的相对方位，不是地图的东边"（红线②立靶）。
- 动手：已知北京 20:00，点纽约 → 现象：跨日界线警示"日期减一天" → 结论："向东跨过日界线，日期减一天——时间可以'追'，日期要'找回来'"（pedagogy T3 边界）。

### 蓝队评审

- ✅ **可实现**：原生 JS + SVG（时区盘）+ MathML，零依赖；时区差为整数查表，纯前端。
- 冻结边界：初中默认只做**区时**（整小时加减）；地方时（经度差 15°=1h 精确到分）为高中扩展 param（`mode:"localtime"`，dg14.2.4 严格化页），不在本交互默认开启。
- 性能红线：无。

### 常见坑

1. **方向基准禁"地图右边"**：定东西必须按经度/自转方向算；任何"目标在屏幕右边所以在东"的文案 = 不通过（W-G3，红线②）。
2. **日界线警示不可关**：`dateLineAlert` 默认 true 不可配 false（教学事故防线）。
3. **"北京时间"注脚必有**：页内一句（审计清单第 4 条）。
4. **24 时区盘 390px 点选**：扇形过小，必须配城市列表备选（W-G10 类比 C4 补偿交互）。

## G8 · scale-calc（比例尺换算练习）

三种表示互换（数字式 ↔ 线段式 ↔ 文字式）；图上距离 ↔ 实地距离换算；"大详小略"对比演示（同一城市大小两种比例尺地图联动：范围与详细程度）。
适用课型：**dg01.3.1 比例尺**（跃升 3 立靶页，红线辨析④）；**dg06.1.1 区域认知方法**（红线④回填：大洲图用小比例尺）；**dg12.1.1 秦岭—淮河线**（专题图比例尺选择回填）。

### Schema

| 参数 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| `mode` | string | — | `"convert"` | `"convert"`（三种表示互换）/ `"calc"`（图上↔实地换算）/ `"compare"`（大详小略对比演示） |
| `scales` | array | ✅ | — | 比例尺：每项 `{rep:"1:50000"（数字式）, text（文字式，如"图上 1 厘米代表实地 500 米"), bar:{unit（如"cm"), segments（如 4)}（线段式）}` |
| `tolerance` | string | — | `"1%"` | 换算容差：相对误差 ±1% 内算对（见 §15 B6） |
| `compareMaps` | array | — | — | `mode:"compare"` 时必填：两幅示意地图 `{scale, label（如"大比例尺：看得细、范围小")}` 联动演示 |
| `motto` | string | — | 冻结 | 口诀冻结为"**大详小略**" + 换算句"分母越小、比例尺越大"（红线④，见 §15 B7） |

- 互换：给数字式 → 学生填文字式/画线段式（线段式为点选刻度）；三种表示等价徽章"三种说法，一回事 ✓"。
- 换算：图上距离（cm）× 比例尺 → 实地距离（m/km）；单位换算 cm→m→km 一步一示（"1km = 100000cm"桥梁句，黄队配）。
- 对比演示：同一城市两幅示意地图，滑块切比例尺 → 范围框联动缩放 + "范围/详细程度"双读数（"范围变小、内容变详细"）。

### 示例

```js
interaction: {
type: "scale-calc",
params: {
mode: "calc",
scales: [{ rep: "1:50000", text: "图上 1 厘米代表实地 500 米", bar: { unit: "cm", segments: 4}}],
tolerance: "1%"
}
}
```

### 输入 / 输出

- 输入：填空（文字式/换算结果）/ 线段式点选 / 对比滑块。
- 输出：✓/✗ + 换算步骤展示（"图上 2cm × 50000 = 100000cm = 1km"）；对比模式输出范围/详细程度联动。

### 触控要求

- 填空框 ≥ 44px 高（`inputmode="decimal"`）；线段式刻度点选 ≥ 44px；对比滑块 ≥ 44px。

### 深色模式

- 地图示意 `--geo-line`；读数文字走 `--geo-text`；✓/✗ 用 `--geog-correct`/`--geog-wrong`。

### 双编码

- 三种表示：数字 + 文字 + 线段图形（三编码）；大/小：文字"大详小略" + 范围框大小对比。

### 复用几何

- 分步换算复用化学 Y12 `stoich-steps`（一步一核对）；填空校验为查表比对（容差 ±1%）。

### 黄队接口（先动手后结论）

- 动手：对比滑块从小比例尺拨到大比例尺 → 现象：地图范围框缩小、街道变多 → 结论点题："大详小略——比例尺大，看得细，但看的范围小"（红线④立靶）。
- 动手：图上 2cm，1:50000 → 现象：一步步算出 1km → 结论："比例尺是图上距离和实地距离的比——比值，不是图的大小"。

### 蓝队评审

- ✅ **可实现**：原生 JS + DOM（填空/校验）+ SVG（线段式/对比地图示意），零依赖；换算纯前端。
- 性能红线：无。

### 常见坑

1. **"大/小"指比值**：口诀必须配"分母越小、比例尺越大"换算句（pedagogy T6）；"图大=比例尺大"是头号误区，页内明示"比值大，不是纸大"。
2. **单位桥梁句必有**：cm→km 换算的"1km=100000cm"一步一示，不许跳步（初中量级感，审计清单第 7 条）。
3. **对比地图标"示意"**：两幅对比图为示意，"示意"声明常驻（W-G8）。

## G9 · plate-puzzle（板块拼图/漂移）

大陆轮廓拖拽拼图（南美—非洲拼合，海岸线"严丝合缝"）；拼合后叠加三证据点（古生物化石/岩层/冰川痕迹）；
六大板块着色 + 边界运动方向箭头（挤压/张裂）；"一年几厘米"数量级标注。
适用课型：**dg02.2.2 板块构造**（跃升 8 立靶页）；**dg14.4.2 地貌**（板块→地貌回填）。

### Schema

| 参数 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| `mode` | string | — | `"drift"` | `"drift"`（大陆漂移拼合：南美—非洲）/ `"plates"`（六大板块着色 + 边界箭头） |
| `pieces` | array | — | — | `mode:"drift"` 时必填：大陆拼块 `{id, name, shapeRef}`（示意轮廓，无国界线） |
| `evidences` | array | — | — | 拼合后叠加的证据点：每项 `{kind:"fossil"/"strata"/"glacier", label（如"中龙化石"), at:[x,y]}` |
| `boundaries` | array | — | — | `mode:"plates"` 时必填：边界 `{kind:"convergent"/"divergent", at:[x,y], label（如"喜马拉雅山：碰撞挤压")}` |
| `rateNote` | string | — | 冻结 | 数量级标注冻结为"板块一年移动几厘米——指甲长的速度"（见 §15 B9；黄队不可改写量级） |
| `driftAnim` | boolean | — | `true` | 是否播放大陆漂移示意动画（"示意，非真实速度"常驻） |

- 拼合判定：南美—非洲拼块边缘贴合度 ≥ 阈值（内部参数）→ 吸附 + "严丝合缝 ✓" + 三证据点逐个点亮（点证据看一句说明）。
- 六大板块：六色定版（pedagogy 第八章：亚欧黄/非洲橙/印度洋红/太平洋蓝/美洲绿/南极洲灰）+ 板块名文字 + 边界线加粗；
边界箭头：挤压（相向箭头 + "挤压"文字）/ 张裂（相背箭头 + "张裂"文字）。
- 超纲词边界：dg02 页**不许出现**"消亡边界/生长边界"术语（pedagogy 超纲词清单），用"挤压/张裂"人话；术语在 dg14.4.2 严格化页首次出现。

### 示例

```js
interaction: {
type: "plate-puzzle",
params: {
mode: "drift",
pieces: [
{ id: "sa", name: "南美洲", shapeRef: "path:sa"},
{ id: "af", name: "非洲", shapeRef: "path:af"}
],
evidences: [
{ kind: "fossil", label: "中龙化石：两岸都有", at: [48, 52]},
{ kind: "strata", label: "岩层：拼合处连续", at: [52, 48]},
{ kind: "glacier", label: "冰川痕迹：都在南半球", at: [50, 60]}
],

}
}
```

### 输入 / 输出

- 输入：拖大陆拼块拼合 / 点证据点 / 板块模式点边界。
- 输出：拼合吸附 + 三证据点亮 + 边界箭头 + "一年几厘米"数量级徽章。

### 触控要求

- 大陆拼块热区 ≥ 44px；证据点热区 ≥ 44px；边界点选 ≥ 44px。

### 深色模式

- 六大板块色深色自动提亮（`--geog-plate-a` 系）；边界线加粗深色可辨；
- 证据点 `--geog-highlight` + 文字。

### 双编码

- 板块：颜色 + 板块名文字 + 边界加粗线；挤压/张裂：箭头方向 + 文字；
- 证据：图标 + 文字说明（三证据缺一不可）。

### 复用几何

- 拖放拼合复用 `cut-reassemble`；证据点点选复用 `tap-highlight`。

### 黄队接口（先动手后结论）

- 动手：把南美洲往非洲拼 → 现象："严丝合缝" + 三证据点亮 → 结论点题："拼图能拼上，不是巧合——化石、岩层、冰川三处证据都对上了，大陆真的在动"。

### 蓝队评审

- ✅ **可实现**：原生 JS + SVG（示意轮廓构建时内嵌），零依赖；拼合判定为边缘距离阈值，纯前端。
- ⬇ **主动降级（教学聚焦）**：大陆漂移动画只做"拼合↔分开"两帧示意，**不做连续亿年时间轴漂移动画**（真实理由：技术上可实现，但连续时间轴的"中间态"无教学锚点（学生记不住 1 亿年前 vs 5000 万年前的区别），两帧对比已达成"大陆在动"的教学目标，QA 成本 ROI 为负）。
- 性能红线：无。

### 常见坑

1. **"漂"的边界句必有**：页内一句"软流层是塑性固体，板块在缓慢移动——不是船浮在水面"（pedagogy T9）。
2. **超纲词冻结**：dg02 页禁"消亡边界/生长边界"（pedagogy 超纲词清单；白队按附校验清单拦）。
3. **大陆轮廓无国界线**：示意轮廓只画海岸线（国界口径硬约束）。
4. **"一年几厘米"量级冻结**：见 §15 B9；不许写成"一年几米"。

## G10 · pop-pyramid（人口金字塔）

人口年龄结构金字塔：拖"年份"滑块看形态变化（扩张型 → 稳转型 → 收缩型）；
中国/日本/尼日利亚三国对比；读数徽章显示老年人口比重、抚养比（**初中只给定性、定量为高中版**）。
适用课型：**dg04.1.2 人口问题**；**dg08.2.1 中国的人口**；**dg15.1.1 人口迁移与人口问题**（高中版）。

### Schema

| 参数 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| `countries` | array | ✅ | — | 国家：每项 `{name（如"中国"), years:[{year, male:[...], female:[...], agedShare?, dependencyRatio?}]}`；年龄组 5 岁一档 |
| `yearSlider` | object | — | `{min:1950,max:2050,step:10,init:2020}` | 年份滑块（步进 10 年；未来年份配"预测"文字） |
| `compareMode` | boolean | — | `false` | 三国对比模式（并排三金字塔，`countries` ≥ 3 时可用） |
| `quantitative` | boolean | — | `false` | 是否显示定量读数（老年人口比重/抚养比）；**冻结：初中页必须 `false`**（见 §15 B10；高中 dg15.1.1 页可 `true`） |
| `typeBadge` | boolean | — | `true` | 是否显示金字塔类型徽章（"扩张型/稳定型/收缩型"文字 + 形态描述） |

- 金字塔：左男右女（蓝/朱红 + "男"/"女"文字，双编码）；年份拖动 → 条形联动 morph（CSS transition，不跳变）；
类型徽章实时判定（底部宽=扩张 / 上下均匀=稳定 / 顶部宽=收缩）。
- 数据年份：每组数据注年份（如"2020 年第七次人口普查"，审计清单第 10 条）；预测年份（>2026）配"预测"文字 + 虚线边框（与历史数据视觉区分）。
- 初中定性版：`quantitative:false` 时只显示类型徽章 + 一句人话（"下面宽 = 年轻人多"）；高中版 `quantitative:true` 显示老年人口比重、抚养比读数（MathML）。

### 示例

```js
interaction: {
type: "pop-pyramid",
params: {
countries: [
{ name: "中国", years: [{ year: 2020, male: [...], female: [...], agedShare: 18.7, dependencyRatio: 45.9}]}
],
yearSlider: { min: 1982, max: 2050, step: 10, init: 2020},
compareMode: false, quantitative: false, typeBadge: true
}
}
```

### 输入 / 输出

- 输入：年份滑块 / 国家切换 / 对比模式。
- 输出：金字塔 morph + 类型徽章（扩张/稳定/收缩）+（高中版）定量读数。

### 触控要求

- 年份滑块 ≥ 44px；国家切换按钮 ≥ 44px；390px 下三国对比纵向排布。

### 深色模式

- 男/女条形 `--geog-known`/`--geog-target` 深色提亮 + "男/女"文字；预测年份虚线边框深色可辨。

### 双编码

- 性别：颜色 + "男/女"文字 + 左右位置；类型：文字徽章 + 形态描述（"下面宽"）；
- 历史/预测：实线/虚线边框 + "预测"文字。

### 复用几何

- 滑块范式复用代数 `slider-lab`；三国对比排布复用物理 Y5 `side-compare` 的 390px 堆叠约定。

### 黄队接口（先动手后结论）

- 动手：拖年份从 1982 到 2050（预测）→ 现象：金字塔从"下面宽"变成"上面宽" → 结论点题："扩张型 → 收缩型——年轻人少了、老年人多了，这就是老龄化"。
- 对比动手：切日本 vs 尼日利亚 → 现象：一个"头重脚轻"、一个"底座巨大" → 结论："人口问题有两副面孔：太多和太老，都是问题"（dg04.1.2）。

### 蓝队评审

- ✅ **可实现**：原生 JS + SVG（条形）+ MathML，零依赖；morph 为条形长度 transition，纯前端。
- 离线预计算：无（数据构建时内嵌）。
- 性能红线：年龄组 ≤ 21 组/性别；三国对比 ≤ 3 国。

### 常见坑

1. **`quantitative` 初中冻结 false**：初中页出现抚养比数字 = 不通过（pedagogy Y23 注 + §15 B10；超纲词规范）。
2. **数据注年份**：每组数据 `year` 必填；预测年份必须标"预测"（W-G7）。
3. **"约"字诚实**：预测数据读数写"约"（审计清单第 7 条）。
4. **类型判定阈值冻结**：扩张/稳定/收缩判定规则见 §15 B10（黄队确认，蓝队实现）。

## G11 · monsoon-sim（季风环流模拟）

冬/夏两季切换：陆地/海洋气压高低着色（H/L）；海陆间风向箭头动画；武汉冬夏风向/降水联动读数；
配"沙子 vs 水升温"热力差异小实验（两杯对比：加热滑块 → 沙子升温快）。
适用课型：**dg14.3.2 季风**（跃升 7 立靶页）；**dg09.2.1 中国的气候**（季风回填）。

### Schema

| 参数 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| `season` | string | — | `"winter"` | `"winter"`（冬季）/ `"summer"`（夏季）；两季切换按钮（≥44px） |
| `showPressure` | boolean | — | `true` | 陆地/海洋气压高低着色（H/L + 文字，沿用 G5 脱钩约定） |
| `cityLink` | object | — | — | 城市联动读数（如 `{name:"武汉", winter:"偏北风、干冷少雨", summer:"偏南风、暖湿多雨"}`，黄队配） |
| `heatLab` | boolean | — | `true` | 是否配"沙子 vs 水升温"小实验（加热滑块 → 两条升温曲线，沙子陡、水缓） |
| `frameNote` | string | — | 冻结 | 冻结文案："冬/夏两帧对比示意，非逐月连续模拟"（见蓝队评审降级项） |

- 两帧对比：冬季 = 陆地冷高压（H）→ 风从陆地吹向海洋（偏北干冷）；夏季 = 海洋高压 → 风从海洋吹向陆地（偏南暖湿）；
风向箭头动画（`--geog-warm`/`--geog-cold` + 箭头 + "偏北风"/"偏南风"文字）。
- 热力小实验：加热滑块 → 沙子/水两条升温曲线（`--geog-target` 朱红陡 / `--geog-known` 蓝缓）+ 读数"同样加热，沙子升温快"；
结论桥接："陆地像沙子、海洋像水——这就是季风'掉头'的力气来源"。
- 气压带季节移动：只做示意箭头（"夏季气压带北移"一句），**不做数值模拟**（降级项）。

### 示例

```js
interaction: {
type: "monsoon-sim",
params: {
season: "winter",
showPressure: true,
cityLink: { name: "武汉", winter: "偏北风、干冷少雨", summer: "偏南风、暖湿多雨"},
heatLab: true
}
}
```

### 输入 / 输出

- 输入：冬/夏切换 / 加热滑块（小实验）。
- 输出：风向箭头动画 + H/L 着色切换 + 武汉冬夏联动读数 + 升温曲线对比。

### 触控要求

- 冬/夏切换按钮 ≥ 44px；加热滑块 ≥ 44px；风向箭头只读（不可拖）。

### 深色模式

- H/L、风向箭头深色自动提亮；升温曲线 `--geog-temp`/`--geog-precip` 类比色 + 文字。

### 双编码

- 季节：按钮文字"冬季/夏季" + 场景着色；风向：箭头 + "偏北风/偏南风"文字；
- H/L：字母 + 图例脱钩声明（沿用 G5）。

### 复用几何

- 冬/夏两帧切换复用化学 Y6 `tri-rep` 的 tab 切换范式（一次只显示一帧，防信息过载）；
- 升温曲线描点复用代数 `plot-points`。

### 黄队接口（先动手后结论）

- 动手：先玩"沙子 vs 水"加热 → 现象：沙子升温快 → 动手切夏季 → 现象：风向从陆地吹向海洋"掉头" → 结论点题："季风是'会掉头的风'——陆地像沙子、海洋像水，夏天海洋的湿气被吹进陆地"（跃升 7）。

### 蓝队评审

- ✅ **可接（新增类型）**：原生 JS + SVG + MathML，零依赖；两帧切换 + 箭头动画，纯前端。
- ⬇ **主动降级（教学聚焦）**：只做冬/夏两帧对比，**不做逐月连续风场动画**（真实理由：技术上可实现，但黄队痛点是"双重成因一次讲清会噎住"——两帧对比恰好分两步（先热力差异小实验、后冬夏风向），逐月连续动画信息过载且风场插值的真实性 QA 成本高，ROI 为负）。
- 性能红线：无。

### 常见坑

1. **"掉头"边界句必有**：页内一句"东亚季风风向季节相反；南亚季风还受气压带季节移动影响"（pedagogy T8）。
2. **两帧冻结文案**：`frameNote` 不可删（防学生当成"只有两天有季风"）。
3. **季风 ≠ G5 行星风系**：页内一句"季风是海陆热力差异叠加在行星风系上的'季节反转'"（防概念混淆；超纲词：dg14.3.2 前不许出现"季风环流"机制术语，pedagogy 超纲词清单）。

## G12 · region-overlay（区域要素叠图）

同一区域多图层开关（地形/气候/河流/人口/交通/产业）：默认开启 ≤3 层；切换时顶部明示当前叠加；
"关掉某层看结论变化"思想实验（如"如果没有长江，武汉还会是九省通衢吗？"）。
适用课型：**dg12.1 秦岭—淮河线**（跃升 9 立靶页：一线六义图层叠加）；**dg13 各区域课**；**dg15.2.1 产业区位**（Y22 联动）。

### Schema

| 参数 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| `region` | string | ✅ | — | 区域名（如"秦岭—淮河线两侧"、"武汉及周边"，黄队配） |
| `layers` | array | ✅ | — | 图层：每项 `{id, name（如"地形"), kind:"terrain"/"climate"/"river"/"pop"/"traffic"/"industry", visible（默认开关）, dataRef}`；`dataRef` 为图层数据引用（构建时内嵌，见 §15 B12） |
| `maxVisible` | number | — | `3` | 同时开启图层上限（冻结 ≤3，见 pedagogy 全局约定；超限时提示"先关掉一层"） |
| `thoughtExp` | object | — | — | 思想实验：`{offLayer（关掉的图层 id）, question（如"如果没有长江，武汉还会是九省通衢吗？"), hint}`；一键关层 → 结论变化提示 |
| `stackBadge` | boolean | — | `true` | 顶部是否明示当前叠加（"当前：地形 + 河流 + 交通"，默认 true 不可关闭） |

- 图层开关：chips 式开关（≥44px），一次只显示叠加结果；`stackBadge` 常驻顶部（"当前：××+××"，沿用化学 Y6"现在看：××"范式）。
- 思想实验：点"试试关掉长江" → 河流层关闭 → 交通/产业层高亮变化 + `hint`（"没了黄金水道，九省通衢要打折扣"）→ 再打开恢复。
- 秦岭—淮河线预设：`layers` 配六层（1 月 0℃ 等温线/800mm 年等降水量线/温度带界线/干湿区界线/水田旱地/水稻小麦），默认开启 ≤3 层，一线六义逐层点亮。

### 示例

```js
interaction: {
type: "region-overlay",
params: {
region: "秦岭—淮河线两侧",
layers: [
{ id: "temp", name: "1 月 0℃ 等温线", kind: "climate", visible: true},
{ id: "precip", name: "800mm 年等降水量线", kind: "climate", visible: true},
{ id: "farm", name: "水田/旱地", kind: "industry", visible: false}
],
maxVisible: 3,
thoughtExp: { offLayer: "river", question: "如果没有长江，武汉还会是九省通衢吗？", hint: "没了黄金水道，交通区位要打折扣——区位是要素叠加的结果"},

```

### 输入 / 输出

- 输入：图层开关 chips / 思想实验一键关层。
- 输出：叠加地图重绘 + 顶部当前叠加明示 + 思想实验结论提示。

### 触控要求

- 图层 chips ≥ 44px；390px 下 chips 横滑不溢出（一屏）。

### 深色模式

- 各图层语义色深色自动跟随；叠加时图层透明度保证可辨（W-G13 抽查）。

### 双编码

- 图层：颜色 + 图例文字 + `stackBadge` 文字明示；思想实验：文字问题 + 结论提示。

### 复用几何

- tab/chips 切换范式复用化学 Y6 `tri-rep`（切换必明示当前视角）；
- 图层开关状态机为地理新增（纯 DOM）。

### 黄队接口（先动手后结论）

- 动手：秦岭—淮河线六层逐层点亮 → 现象：一线两侧，气温、降水、温度带、干湿区、耕地、作物各不同 → 结论点题："这条线是'中国南北的分界线'——一线六义，线南线北各不同"（跃升 9）。
- 动手：关掉"河流"层 → 现象："九省通衢"结论动摇 → 结论："区位没有单因——是要素叠加的结果"（第九条铁律组件落地）。

### 蓝队评审

- ✅ **可接（新增类型）**：原生 JS + SVG 图层叠加（各图层为独立 SVG 组，开关即显隐），零依赖；纯前端。
- ⬇ **主动降级（教学聚焦）**：图层为**预置静态图层**（黄队按区域配），**不做"学生自由上传数据生成新图层"**（真实理由：技术上可实现，但自由图层的数据清洗/投影对齐 QA 成本极高，初中教学用预置图层已达成"综合观"目标）。
- 性能红线：单区域图层 ≤ 6 个；同时可见 ≤ 3（`maxVisible` 冻结）。

### 常见坑

1. **`maxVisible` 冻结 ≤3**：默认开启 >3 层 = 不通过（pedagogy 全局约定；信息过载）。
2. **`stackBadge` 不可关**：切换不写明当前叠加 = 不通过（W-G13；沿用 Y6 W-C15）。
3. **"分界线"边界句**：秦岭—淮河线页必有一句"过渡带，**大致**以这条线为界"（pedagogy T10）。
4. **思想实验是"关层看变化"**：不是删除数据——`thoughtExp` 关层后必须能一键恢复（防学生以为长江没了）。

## G13 · site-select（产业区位权衡器）

三个候选城市（原料/市场/交通/劳动力/政策参数卡）；学生为"钢铁厂/软件园/服装厂"分别选址并**拖拽排序权重**；
提交后显示"不同产业答案不同"；配"称权重"口诀（"先问这个产业最怕缺什么"）。
适用课型：**dg15.2.1 产业区位**（跃升 10 立靶页）。

### Schema

| 参数 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| `industries` | array | ✅ | — | 产业：每项 `{name（如"钢铁厂"), motto（如"最怕缺原料和交通")}`；黄队配 3 个 |
| `candidates` | array | ✅ | — | 候选城市：每项 `{name, factors:{原料:1-5, 市场:1-5, 交通:1-5, 劳动力:1-5, 政策:1-5}}`（参数卡，黄队按案例配，见 §15 B13） |
| `weightOrder` | array | — | `["原料","市场","交通","劳动力","政策"]` | 权重排序初始顺序；学生拖拽排序（越前权重越大） |
| `verdictRule` | string | — | 冻结 | 冻结："按学生排的权重 × 黄队配的参数卡计分，展示'不同产业答案不同'；**权重分是教学演示分，不是经济预测**"（见 §15 B13） |
| `motto` | string | — | 冻结 | 口诀冻结为"**称权重：先问这个产业最怕缺什么**"（pedagogy T12；黄队不可改写） |

- 权重拖拽：五个因素 chips 拖拽排序（`cut-reassemble` 同构）；排好 → 点"算一算" → 各城市得分条（`--geog-known` + 分数 + 排名文字）。
- 产业切换：切"软件园" → 同样的三城市、学生重排权重 → 得分条变化 → 结论徽章"同样的城市，不同的答案——区位没有标准答案，只有权重不同"。
- 诚实声明：得分条旁常驻小字"权重是你的排序，参数是老师配的案例分——演示'权重思想'，不是算命"（`verdictRule` 落地）。

### 示例

```js
interaction: {
type: "site-select",
params: {
industries: [
{ name: "钢铁厂", motto: "最怕缺原料和交通"},
{ name: "软件园", motto: "最怕缺人才和市场"}
],
candidates: [
{ name: "武汉", factors: { 原料: 3, 市场: 4, 交通: 5, 劳动力: 4, 政策: 4}},
{ name: "黄石", factors: { 原料: 5, 市场: 2, 交通: 3, 劳动力: 3, 政策: 3}}
]
}
}
```

### 输入 / 输出

- 输入：拖拽排序权重 / 切换产业 / 点"算一算"。
- 输出：各城市得分条 + 排名 + "不同产业答案不同"结论徽章。

### 触控要求

- 权重 chips 拖拽热区 ≥ 44px；"算一算"按钮 ≥ 44px；产业切换 ≥ 44px。

### 深色模式

- 得分条 `--geog-known` 深色提亮 + 分数文字；徽章文字走 `--geo-text`。

### 双编码

- 得分：条长 + 分数数字 + 排名文字；权重：排序位置 + 数字序号（"① 原料"）。

### 复用几何

- 拖拽排序复用 `cut-reassemble`（散块 → 权重 chips）；得分条为地理新增（纯 DOM）。

### 黄队接口（先动手后结论）

- 动手：给钢铁厂排权重（原料①、交通②）→ 现象：黄石得分反超武汉 → 动手切软件园重排（劳动力①、市场②）→ 现象：武汉反超 → 结论点题："区位没有标准答案，只有'权重'不同——原料对钢铁厂是命，对软件园是路人"（跃升 10）。

### 蓝队评审

- ✅ **可接（新增类型）**：原生 JS + DOM，零依赖；计分为加权求和（权重按排序位线性递减，黄队确认），纯前端。
- ⬇ **主动降级（教学聚焦）**：**不建真实经济投入产出模型**（真实理由：技术上可实现，但真实区位模型的变量（运费函数、集聚经济）远超初中教学目标；教学目标是"权重思想"，黄队配参数卡 + 透明计分已达成。计分公式冻结并公示给学生——"演示权重思想，不是经济预测"）。
- 性能红线：无。

### 常见坑

1. **诚实声明不可删**：得分条旁"演示权重思想，不是算命"小字缺失 = 不通过（W-G14 类比）。
2. **参数卡黄队配**：`candidates[].factors` 的 1–5 分由黄队按真实案例配（见 §15 B13），蓝队不编造"某市原料 5 分"。
3. **权重算法冻结公示**：计分公式（排序位线性权重）写进页内小字，学生可复算（防"黑箱打分"误解）。
4. **"称权重"口诀冻结**：见 §15 B13；T12 的"生造词"担忧由地理专家队裁决后定稿（当前用冻结版）。

**零二进制资源**：G1 地球仪为 Canvas 绘制的示意球（非纹理贴图），G3/G7/G9 轮廓为构建时内嵌的简化 SVG 路径。

### 12.2 主动降级项（一句话版）

1. **G2 晨昏线**：⬇ 主动降级（教学聚焦）——真实大气散射/曙暮光渐变降级为一条清晰晨昏线。（真实理由：初中教学目标是"昼夜分界 + 昼长变化"，曙暮光分级属高中拓展，零依赖实现 ROI 为负。）
2. **G3 等高线 3D**：⬇ 主动降级（教学聚焦）——真实 DEM 数据加载降级为四种参数化地形模板；3D 为 2.5D 示意山体（非 WebGL）。（真实理由：真实 DEM 在零依赖/file:// 下体积与加载 ROI 为负；教学目标是"等高线↔地形对应关系"，参数化模板已达成。）
3. **G5 风带洋流**：⬇ 主动降级（教学聚焦）——风场粒子实时模拟不做，只做示意环流圈 + 风向箭头。（真实理由：教学目标是"风向规律 + 洋流影响"，粒子流场属可视化噱头，QA 与性能成本 ROI 为负。）
4. **G7 区域拼图**：⬇ 主动降级（教学聚焦）——"空白轮廓上徒手画省界"不做，只做形状+简称+中心三配对。（真实理由：手绘省界判定 QA 成本过高，且省界走向属口径敏感区；三配对已达成教学目标。）
5. **G9 板块拼图**：⬇ 主动降级（教学聚焦）——连续亿年时间轴漂移动画降级为"拼合↔分开"两帧示意。（真实理由：连续时间轴的中间态无教学锚点，两帧对比已达成"大陆在动"目标。）
6. **G11 季风**：⬇ 主动降级（教学聚焦）——逐月连续风场动画降级为冬/夏两帧对比；气压带季节移动只做示意箭头。（真实理由：黄队痛点是"双重成因一次讲清会噎住"，两帧分两步恰好解耦；逐月动画信息过载且风场插值真实性 QA 成本高。）
7. **G12 要素叠图**：⬇ 主动降级（教学聚焦）——学生自由上传数据生成图层不做，只做黄队预置静态图层。（真实理由：自由图层的数据清洗/投影对齐 QA 成本极高，预置图层已达成"综合观"目标。）
8. **G13 区位权衡**：⬇ 主动降级（教学聚焦）——真实经济投入产出模型不做，权重分=教学演示分并公示计分公式。（真实理由：真实区位模型变量远超初中目标；教学目标是"权重思想"，透明计分已达成。）

### 12.3 性能红线（地理页）

## §14 与黄队教学的接口：教学动作链
