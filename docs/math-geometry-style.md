# 数学 · 几何 视觉与交互规范（蓝队 v1.0）

> 对应家长任务：M4 颜色双编码 / M5 深色模式 / M6 交互反馈规范。
> 与 `docs/math-geometry-pedagogy.md`（黄队）第 5 章的全局颜色约定配套：对应元素永远同色、已知条件蓝色、求证目标红色系、辅助线灰色虚线。本文件把"哪一色"、"色盲怎么办"、"深色模式用什么色"、"震动怎么反馈"定死，几何生产全书照此执行。
> 全局铁律（沿用 `math-interaction-params.md`）：`params` 中不出现具体色值，只用 CSS 变量；逻辑单位不写死 px。

## 一、M4 · 色板：Okabe-Ito（色盲友好）

采用 Okabe-Ito 8 色（Wong, 2011），为红绿色盲、蓝黄色盲优化过，在常见色盲模拟下 8 色两两可辨。所有几何图形的描边/填充只从这 8 色取，**不自创颜色**。

| 色名 | Hex | 几何用途（全书固定） |
|---|---|---|
| 橙 Orange | `#E69F00` | 对应边 A 组描边 / 切割拼补编号块① |
| 天蓝 Sky blue | `#56B4E9` | 对应边 B 组描边 / 切割拼补编号块② |
| 蓝绿 Bluish green | `#009E73` | 对应边 C 组描边 / 切割拼补编号块③ |
| 黄 Yellow | `#F0E442` | 高亮闪烁 / 不变量徽章强调底色（配深色字） |
| 蓝 Blue | `#0072B2` | **已知边、已知条件**（对齐教学设计"已知用蓝色"） |
| 朱红 Vermillion | `#D55E00` | **待求边、求证目标**（红橙系，对齐教学设计"求证目标用红色"；本色板无纯红，朱红是色盲安全的"红色"替代） |
| 紫红 Reddish purple | `#CC79A7` | 对应角 A 组弧线标记 / 切割拼补编号块④ |
| 黑 Black | `#000000` | 常规描边、坐标轴、点、文字 |

补充说明：

- **辅助线**：中性灰 `#7A7A7A` 虚线（非 Okabe-Ito 色，灰色虚线本身就是"辅助"的线型编码；对齐教学设计"辅助线灰色虚线"）。
- **对应元素同色**：全等/相似三角形对应边用同色（如两组橙/天蓝），对应角用同色弧线；同一题中最多用 3 组对应色（橙、天蓝、蓝绿），超过 3 组时用"同色 + 标记数量"区分（见双编码）。
- 黄色在白底上对比度低，**只用于高亮闪烁和徽章底色（配深色文字）**，不做线条/文字色。

### 双编码规则（颜色 + 几何标记，色盲用户仅凭标记可辨）

**原则：任何信息不得只靠颜色传递。** 同一种关系必须同时有颜色和几何标记；色盲用户关掉颜色仍能读懂全图。

| 关系 | 颜色编码 | 几何标记编码（必备） | 示例 |
|---|---|---|---|
| 等长边 | 同色描边 | **刻度线**：边中点画短横刻度；第一组 1 道、第二组 2 道、第三组 3 道 | 两条橙色边各带 1 道刻度 → 等长 |
| 等角 | 同色弧线 | **弧线**：角内画单弧 / 双弧 / 三弧区分组别 | 两个紫红弧线单弧角 → 相等 |
| 平行线 | 同色描边（可选） | **箭头**：线段中点画单箭头 / 双箭头 / 三箭头 | 两条带双箭头的线 → 平行 |
| 直角 | 不依赖颜色 | **方块**：直角顶点画小正方形 | 方块 = 90°，与颜色无关 |
| 待求/求证 | 朱红 `#D55E00` | **加粗描边 + "？"标记**（或待求量标签如 `x`） | 朱红粗线段 + `?` → 这是要求的那条 |
| 已知 | 蓝 `#0072B2` | **实线 + 数值标签**（如 `5`、`60°`） | 蓝线标 `5` → 已知长度 5 |
| 辅助线 | 灰虚线 | **虚线线型**本身即标记；作图时带"作图步骤编号" | 灰虚线 → 辅助线，一看线型就知道 |

检验方法（白队 QA 用）：把页面截图转灰度（或用色盲模拟器过一遍），所有等长/等角/平行/直角/待求关系仍可凭标记辨认，即为通过。红队/黄队新增标记类型时，必须先在白队清单登记。

## 二、M5 · 深色模式专用色值

深色模式不是"反色"，而是**同色系提亮**：保持浅色模式的色相语义（蓝=已知、朱红=求证），只提高明度，保证在深底 `#121212` 上线条/文字清晰可辨。

### 2.1 主题 CSS 变量（浅色 / 深色）

```css
:root {
  --geo-bg: #FFFFFF;
  --geo-text: #1A1A1A;
  --geo-known: #0072B2;        /* 已知：蓝 */
  --geo-target: #D55E00;       /* 待求/求证：朱红 */
  --geo-corr-a: #E69F00;       /* 对应 A：橙 */
  --geo-corr-b: #56B4E9;       /* 对应 B：天蓝 */
  --geo-corr-c: #009E73;       /* 对应 C：蓝绿 */
  --geo-corr-angle: #CC79A7;   /* 对应角：紫红 */
  --geo-line: #000000;         /* 常规描边 */
  --geo-aux: #7A7A7A;          /* 辅助线（灰虚线） */
  --geo-grid: #E5E5E5;         /* 网格线 */
  --geo-highlight: #F0E442;    /* 高亮：黄（配深色字） */
}
[data-theme="dark"] {
  --geo-bg: #121212;
  --geo-text: #F5F5F5;
  --geo-known: #56B4E9;        /* 已知：提亮为天蓝 */
  --geo-target: #FF7043;       /* 求证：提亮朱红 */
  --geo-corr-a: #FFB020;       /* 对应 A：提亮橙 */
  --geo-corr-b: #7FD4FF;       /* 对应 B：更亮天蓝 */
  --geo-corr-c: #3DDC97;       /* 对应 C：提亮蓝绿 */
  --geo-corr-angle: #E69BBE;   /* 对应角：提亮紫红 */
  --geo-line: #F5F5F5;         /* 常规描边：近白 */
  --geo-aux: #9E9E9E;          /* 辅助线：浅灰虚线（深底上加亮） */
  --geo-grid: #333333;         /* 网格线：深灰，弱对比不抢戏 */
  --geo-highlight: #F0E442;    /* 高亮：黄色在深底上直接可用 */
}
```

### 2.2 深色模式三项专用色（M5 必解项）

| 用途 | 深色值 | 说明 |
|---|---|---|
| 辅助线 | `#9E9E9E` 虚线 | 浅色模式的 `#7A7A7A` 在深底上太暗，提亮一级；虚线线型不变 |
| 网格线 | `#333333` | 只做背景参考，弱对比（约 1.6:1 于底色），不与图形线条混淆 |
| 高亮色 | `#F0E442`（黄） | 深底上黄色天然高对比；闪烁时配深色文字/描边 |

对比度要求（白队 QA 抽查）：深色下正文文字与底色 ≥ 4.5:1（`#F5F5F5` / `#121212` ≈ 15:1）；图形线条与底色 ≥ 3:1；网格线允许低于 3:1（装饰性）。深色模式下**双编码规则不变**——标记（刻度/弧线/箭头/方块）与浅色模式完全一致，只是颜色取深色列。

### 2.3 主题切换约定

- 跟随系统 `prefers-color-scheme`，同时在页面角落提供手动切换按钮（记住用户选择，`localStorage`）。
- MathML 公式渲染走同一套变量（`--geo-text`），深色下公式不变黑看不见。
- 切换主题时不重绘画布，只换 CSS 变量（几何数据 `modules/math/data/gNN.js` 与主题无关）。

## 三、M6 · 交互反馈规范

### 背景结论

`navigator.vibrate` 在 iOS Safari 上**无效**（调用静默无效果），且桌面端根本无震动硬件。几何交互的用户有一半以上在手机/平板上，其中 iPhone 占大头。因此：**吸附/落定的反馈以视觉为必选项**，`navigator.vibrate` 只是 Android 上的加分项，绝不能是唯一的反馈通道。

### 规范

1. **视觉反馈是必选项**，每个可吸附/可落定的交互必须实现至少一种：
   - **高亮闪烁**：命中瞬间元素描边变为高亮黄 `--geo-highlight`，300ms 后恢复；同时做一次缩放脉冲（1.0 → 1.08 → 1.0，时长 300ms）。
   - **刻度对齐动画**：吸附到网格/目标刻度时，显示一条短暂的对齐引导线（虚线，400ms 淡出），并把吸附点"吸"过去做 150ms 的缓动。
   - 落定（drop/settle）成功：落点处画一个扩散圆环动画（半径 0→24 逻辑单位，300ms 淡出）+ 上述高亮闪烁。
2. **`navigator.vibrate` 是可选加分项**（仅 Android 有效）：
   - 调用前必须做能力检测：`typeof navigator !== 'undefined' && typeof navigator.vibrate === 'function'`，再包 `try/catch`；不支持或抛错时**静默跳过**，不影响视觉反馈。
   - 推荐参数：吸附成功 `vibrate(15)`，落定成功 `vibrate([20, 30, 20])`；时长一律 ≤ 60ms，不许长震。
   - 不许把业务逻辑（如计分、判定对错）挂在震动是否执行上。
3. **音效延续代数约定**：吸附/落定可配短促合成音（Web Audio 现场合成，不加载音频文件——全站零音频文件，见音频 B 方案）；音效与震动一样是加分项，静音设备上视觉反馈必须完整可用。
4. 现有文档中"高亮 + 音效震动"类表述（如 `math-interaction-params.md`），一律按本规范解释：**高亮是必须的，震动是可选的**。

### 给渲染器的参数建议（`modules/math/js/interactions.js` 用）

```js
feedback: {
  visual: "flash" | "align" | "ripple",  // 必填，至少一种
  flashMs: 300,        // 高亮闪烁时长
  pulseScale: 1.08,    // 缩放脉冲峰值
  vibrate: [20, 30, 20] | 15 | null,  // 可选；null = 不震
}
```
