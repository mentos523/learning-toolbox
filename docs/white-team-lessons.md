# 白队前端经验沉淀（通用版 · 可复用数学及其他学科）

> 来源：2026-10-10 英语·词根词缀工具 v13–v18 实战。项目约束：纯静态 HTML/CSS/JS，零依赖（无 CDN、无外部字体），全相对路径，GitHub Pages + `file://` 双兼容。
> 本文档只谈**跨学科通用**的前端经验；学科特有检查（如英语词素高亮）见 `docs/white-checklist.md`（英语专用版）。

---

## 一、一屏布局的约束与技巧

核心铁律：**整页无滚动**（`html,body{height:100%;overflow:hidden}`），所有内容塞进一屏。

1. **纵向空间预算先行**：动手写 CSS 前，先给每个区域定死预算——header（flex:none）/ hero 区（flex:none）/ 主交互区（flex:1）/ 说明区（flex:none, 固定高度）。预算一经定死，后续只允许压缩、不允许膨胀。
2. **`flex:1` 只给主交互区**：拨盘/画布/练习区这类核心组件独占 `flex:1`；说明文字、按钮条一律 `flex:none`。
3. **动态内容区必须固定高度**：凡是内容行数会变的区域（如词义说明、公式推导步骤、提示文字），**禁止用 `min-height` 让它自然撑高**——它会挤压上面的 `flex:1` 区。做法：按"全库最大行数"定死 `height` + `overflow:hidden`。英语页教训：`.dial-mean` 从 `min-height:2.2em` 改为 `height:5em`（容纳 2 行词义），切换词根时拨轮位置纹丝不动。
4. **新增数据后回查预算**：数据扩容（加词根、加公式、加题型）后，必须程序化检查"最大行数"是否突破预算，突破则先调预算再上线，而不是让用户发现错位。
5. **用 `dvh` 不用 `vh`**：移动端浏览器地址栏伸缩会导致 `100vh` 跳动，一律 `height:100dvh`。
6. **横向零溢出**：`white-space:nowrap` 的长文本（如长单词、长公式）必须配 `overflow:hidden;text-overflow:ellipsis`，三端都要测。

## 二、选择器组件设计经验（拨盘 → 通用滚轮选择器）

英语页的双拨盘本质是一个**纵向滚轮选择器**，可直接复用给：数学公式选择器、符号面板、题型切换、章节导航。

1. **结构**：外层 `.wheel-wrap`（`flex:1` 占位）+ 内层 `.wheel`（`overflow-y:auto`）+ 上下 `.wheel-pad` 垫片。垫片高度 =（容器高 − 行高）/2，保证选中项永远居中对齐高亮框；容器尺寸变化时用 `ResizeObserver` 重算。
2. **选中判定防抖**：`scroll` 事件只做 `requestAnimationFrame` 节流 + 140ms settle 防抖，停止滚动后才 `Math.round(scrollTop/itemH)` 落定。狂拨 30 次无错乱、无重复触发。
3. **视觉透视**：离选中项越远越小（scale）、越透明（opacity）、越模糊（blur），约显示 7 项。选中项用高亮框（浅蓝框）而非仅靠颜色，色弱可辨。
4. **三种操作都要通**：触摸滚动、点击直达（`click` 委托到 `.wheel-item`）、键盘方向键（`tabindex` + keydown）。无障碍 `role="listbox/option"` + `aria-selected`。
5. **数据量上限实测**：250 项 → 约 260 个 DOM 节点，浏览器无压力；滚动 59–60fps（headless 软件渲染），堆内存零增长。**通用红线：单个选择器 ≤500 项**，超出则必须加搜索过滤（英语页抽屉搜索 250 项全量遍历 <5ms）。
6. **初始选中必须静默**：`setItems` 后的首次 `go(0)` 不播音效、不播动画、不震动，否则打开页面就"咔哒"一声。

## 三、音效与触觉反馈的实现模式

1. **Web Audio 现场合成，不放音频文件**：短促"卡塔"声用 `OscillatorNode`（triangle 波，2400Hz→1200Hz，0.04 秒衰减到静音，增益 0.04）即可，零外部文件、零加载延迟、零仓库体积。英语页曾为此删掉 7.8MB 的 MP3 目录——**新学科一律不引入音频文件**，全部合成。
2. **AudioContext 懒创建 + resume**：首次交互时再 `new AudioContext()`，`state==='suspended'` 时 `resume()`；全程 try/catch，失败静默。
3. **音效只在"落定"时响一次**：滚动过程中不响，settle 选中后响一声；去重 300ms 内相同事件。
4. **震动**：`navigator.vibrate(8)`（8 毫秒微弱震动），try/catch 包裹，桌面端 `navigator.vibrate` 不存在则自动跳过。**震动与音效同一次事件触发**，保持一致。
5. **卡入动画**：CSS `@keyframes`（scale 1.1 → 1.26 → 1.22，0.18s ease-out），JS 侧 `classList.remove` + 强制重排（`void el.offsetWidth`）+ `add` 重启动画。动画时长 <200ms，不阻塞交互。
6. **提供关闭预期**：音效/震动虽默认开启，但后续学科若用户反馈打扰，应在设置里加开关（英语页暂未加，记为待办）。

## 四、三端适配 Checklist

| 检查项 | 1400px 桌面 | 900px 平板 | 390px 手机 |
|---|---|---|---|
| 一屏无页面滚动 | ✓ | ✓ | ✓ |
| 无横向溢出 | ✓ | ✓ | ✓ |
| 拨盘/主交互区可用高度 | ✓ | ✓ | ✓（最紧张，优先测） |
| 抽屉/侧栏可开合 | 悬停滑出 | 点击 | 点击，自动收起 |
| 字号可读（最小 12px 有效） | ✓ | ✓ | ✓ |
| 触摸目标 ≥44px | — | ✓ | ✓ |

- **手机是第一优先级**：空间最紧张，所有"被挤压"类 bug 都先在 390px 复现。
- **抽屉行为分端**：桌面端悬停滑出、选中后不自动收起；手机端点击开合、选中后自动收起（省空间）。
- **断点**：`1024px` 切桌面/手机两套交互；`620px` 以下再收紧字号与间距。

## 五、降级策略（零依赖项目的生命线）

1. **数据文件缺失可运行**：`data/*.js` 用 `window.XXX || []` 兜底；缺失时显示空态提示（"没有找到"/"暂无收词"），不白屏、不报错。实测：`phon.js` 缺失 → 单词正常显示，音标行自动隐藏。
2. **localStorage 禁用可运行**：所有读写包 try/catch，禁用时回退内存默认值，切换功能不受影响。
3. **`file://` 双击可运行**：不用 `fetch` 加载数据（改用 `<script>` 标签引入 `.js` 数据文件）；不用 ES Module（用 IIFE + `var`）；全相对路径。
4. **字体降级**：特殊符号字体（如 IPA 用 Charis SIL）按 `"Charis SIL", Georgia, serif` 顺序写，缺失时自动回退，实测显示正常。
5. **浏览器特性检测**：`ResizeObserver`、`speechSynthesis`、`navigator.vibrate`、`AudioContext` 用前先 `in` 检测，不支持就静默跳过对应功能。

## 六、性能红线

| 指标 | 红线 | 英语页实测（253 词根 / 1777 词） |
|---|---|---|
| 数据 JS 总体积 | ≤500KB（gzip 前） | roots.js 76KB + phon.js 58KB = 134KB ✓ |
| 单个选择器 DOM 节点 | ≤500 | 250 项 → 260 节点 ✓ |
| 数据解析时间 | ≤50ms | 8ms ✓ |
| 3G 首屏 | ≤2s | <2s ✓ |
| 滚动帧率 | ≥55fps | 59–60fps ✓ |
| 内存泄漏 | 0 增长 | 滚动后堆内存 +0.0MB ✓ |
| 音频文件 | 0 个（全合成） | 0 ✓ |

- **扩容前必须先做白队压力预估**（本项目铁律：白队确认无问题才开工）。音频是最大变量：3000 词 × 美/英 = 6000 个 MP3 ≈ 54MB，直接触发"零 MP3 全合成"决策——**新学科默认不引入任何二进制资源**。
- **仓库体积红线**：GitHub Pages 仓库建议 <500MB；纯文本数据几乎不可能触及，二进制资源是唯一风险源。

## 七、与红/蓝队的协作接口（白队视角）

1. **红队交付 → 白队要查**：红队改数据（如补变体、拆词根）后，白队必须重跑"全库扫描"（如词素可见性、最大行数），因为数据变化会打破 UI 假设。本项目实例：补 11 个音变变体后，词素匹配失败从 12 降为 0。
2. **蓝队交付 → 白队要查**：蓝队加功能后，白队按"三端 + 降级 + 性能"三件套验收，不只看功能通不通。
3. **问题归档格式**：`版本：现象 → 根因 → 修复`，写入 `docs/white-checklist.md`（学科专用）底部"历史问题归档"，防止复发。本项目已归档 v15/v16/v17 三个布局类问题。
4. **用户截图优先于自动化**：用户随手截的图（如"词义被挡住"）定位速度远超自动化脚本——白队的 Playwright 检查负责"确认修复"，用户的眼睛负责"发现问题"。

## 附：新学科启动时白队要做的 5 件事

1. 定纵向空间预算（header/hero/主交互/说明区），写入该学科 CSS 注释。
2. 确认动态内容区的最大行数，定死高度 + `overflow:hidden`。
3. 跑一遍第五节降级清单（`file://`、localStorage 禁用、数据文件缺失）。
4. 跑一遍第六节性能红线（数据体积、DOM 数、首屏）。
5. 建该学科的 `docs/<学科>-checklist.md`（仿 `white-checklist.md`），把学科特有检查写进去。
