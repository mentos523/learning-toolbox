# 蓝队数据工程经验沉淀（通用版）

> 沉淀自英语·词根词缀工具（2026-10-10）：120 词根/374 词 → 253 词根/1777 词，3 轮红蓝对抗 + 3 轮扩词。
> 本文档面向后续学科（数学、物理等）复用。**只讲可复用的通用经验，不讲英语特例。**

---

## 1. 静态数据文件的组织模式

### 1.1 用 `.js` 而不是 `.json`

**经验**：数据文件用 `window.X =...` 的 JS 赋值写法，而非 JSON。

**理由**：

- `file://` 直接双击运行时，`fetch()` 加载 JSON 会被浏览器同源策略拦截；`<script>` 标签加载 JS 则无此限制。
- 零构建、零服务器，纯静态部署（GitHub Pages、对象存储、U 盘拷贝）都跑得通。
- 压缩字段名（`r/v/d/m/w`）即可控制体积，本项目 253 词根/1777 词仅 76KB。

**通用模式**：

```js
// data/topics.js
window.SUBJECT_DATA = [ {...},...];
```

消费侧在 `<script>` 加载后直接用 `window.SUBJECT_DATA`，无需异步加载逻辑。

### 1.2 派生数据拆独立文件

**经验**：派生数据（音标 phon.js）与源数据（roots.js）拆两个文件，用单词拼写作为外键关联。

**理由**：

- 源数据与派生数据的生成管线不同（人工/半人工 vs 程序生成），拆开后各自独立更新，互不污染。
- 缺失派生数据时，消费侧按"字段为空则隐藏该行"降级，页面不崩。
- 本项目 phon.js 60KB，独立加载，缺失/加载失败都不影响主数据渲染。

**通用化**：任何可由程序批量生成的辅助字段（音标、注音、图片索引、难度系数），都应放独立文件，源数据只保留"不可推导"的核心字段。

### 1.3 字段命名约定

- 压缩单字母字段名（`r/v/d/m/w`），数据文件体积小，生成脚本里用长名变量保持可读。
- 枚举值统一格式：词性用 `n./v./adj./adv.` 点分隔；多义用数组 + 数字索引 `mi`，不用嵌套对象。
- **跨学科复用建议**：数学的知识点条目可沿用同构：`{id, name, aliases, meanings[], items: [title, type, content, mi]}`。

## 2. 数据校验的程序化方法

每次数据提交前必须跑完以下校验（脚本化，拒绝人工肉眼检查）：

| 检查项 | 说明 | 本项目实例 |
|---|---|---|
| 语法校验 | `node --check` | roots.js / phon.js |
| 重复检查 | 同一主键下无重复条目 | 词根内单词不重复；双收录单词仅白名单 |
| 引用完整性 | 数字索引不越界 | `mi` 必须 `< m.length` |
| 外键覆盖 | 派生数据覆盖源数据 | 1770/1777 音标覆盖，缺失清单输出 |
| 空条目检查 | 无空词根/空数组 | `mi 越界 0、空词根 0` |
| 排序校验 | 符合既定排序规则 | 按词频降序 |

**通用化**：任何学科的数据管线都应有一份 `validate.py`，输出"通过/失败 + 失败清单"。失败清单直接成为红队审计的输入。程序化校验先行，人工审计只看程序查不出的语义问题。

## 3. 外部数据源的使用经验

| 数据源 | 用途 | 经验 |
|---|---|---|
| `wordfreq`（Python 库） | 单词使用频率 | 离线可用，Top5000 足够；**只做排序和筛选依据，不做收录标准**（教材常用度 ≠ 互联网词频） |
| CMU 词典 + `pronouncing` | ARPAbet → IPA 音标 | 离线，覆盖率高；需自写 ARPAbet→IPA 映射 + 重音符号插入逻辑（ˈ/ˌ + 音节划分） |
| dictionaryapi.dev | 在线词典 API | 仅用于首批种子数据；**不可作为运行时依赖**（项目零外部依赖铁律） |

**通用原则**：

1. **构建时可用外部源，运行时零外部依赖**。所有外部数据在构建阶段内嵌进静态文件。
2. 外部源只解决"有无"问题，不解决"对错"问题——词源归属、翻译准确性必须人工/红队审计。
3. 启发式算法（如字符串匹配找词根归属）的假阳性率极高（本项目 de- 曾误收 deadline/decade），**必须有"删除假阳性"的显式步骤**。
4. 宁缺毋滥：外部源覆盖不到的，留空并 UI 降级，不硬凑。

## 4. 排序策略：按使用频率，而非字母顺序

**经验**：数据按"学习者最可能先遇到"的顺序排，而非字母顺序。

**本项目做法**：

- 词根内部：单词按 `wordfreq` 频率降序。
- 词根之间：按旗下最高频单词的频率降序。
- 效果：打开页面第一个词根就是最高频的，学习路径天然从常用到生僻。

**通用化**：

- 数学：知识点按"考试出现频率 / 教材章节顺序"排，而非按名称字母序。
- 排序键必须是**可计算的客观指标**（词频、考频、章节号），不能是人工拍脑袋的"重要度"。
- 排序脚本与数据分离：数据文件只存条目，排序由构建脚本按外部指标重排后写回。

## 5. 增量扩词的工作流

经过 4 轮验证的标准流程（R2-P0/P1/P2、R3）：

```
生成 → 程序化校验 → 红队审计 → 修复 → 推送
↑___________ 红队打回则回到修复 ___________|
```

**关键约束**：

1. **分批**：每批 30–50 个主题单元（本项目：30/50/50 词根），一批一审计，不攒大 batch。
2. **提交不推送**：蓝队生成后 `commit` 到本地分支/本地提交，红队审计通过后才 `push`。线上永远是"已审计"状态。
3. **红队结论只有两种**：或。没有"大致没问题"。
4. **教训必须写进下一批的任务书**：P0 的"跨语源混同"教训写进 P1/P2 任务书后，P1/P2 未再犯。**任务书是跨批次传递经验的载体**。

**通用化**：数学扩充知识点/例题时，同样按"主题批次"推进，每批独立审计。

## 6. 派生数据的生成管线

以音标为例的标准管线：

```
源数据（单词列表）
→ 外部源查询（CMU pronouncing）
→ 格式转换（ARPAbet → IPA，自写映射表）
→ 增量累积（/tmp/phon.json 作为累积缓存，避免重复查询）
→ 写回 phon.js（window.WORD_PHON = {...}）
→ 覆盖率校验（输出缺失清单）
```

**通用要点**：

1. **累积缓存**：中间结果存一份 JSON 缓存，新增数据只查增量，不全量重跑。
2. **转换逻辑自包含**：ARPAbet→IPA 的映射表和重音规则写在脚本里，不依赖在线服务。
3. **缺失可接受**：覆盖率 1770/1777，未覆盖的 7 个由 UI 降级处理（隐藏音标行），不阻塞发布。
4. **数学类比**：公式的 LaTeX 渲染、知识点的难度标注、例题的配图索引，都可走同样管线——源数据只存"题干"，派生数据（渲染结果、难度分）独立生成、独立文件。

## 7. 给数学学科的数据结构建议

基于以上经验，数学模块建议的数据组织：

### 7.1 文件划分

```
modules/math/data/
topics.js # 知识点：window.MATH_TOPICS
formulas.js # 公式（派生/引用）：window.MATH_FORMULAS
problems.js # 例题：window.MATH_PROBLEMS
```

### 7.2 知识点条目（对标词根条目）

```js
{
id: "linear-eq", // 主键（对标 r）
aliases: ["一元一次方程"], // 别名（对标 v）
title: "一元一次方程", // 显示名（对标 d）
meanings: ["含一个未知数、未知数次数为1的方程"], // 定义（对标 m）
items: [ // 下属条目（对标 w）
["3x+5=14", "example", "移项求解", 0],
["ax+b=0(a≠0)", "formula", "标准形式", 0]
]
}
```

- `items` 复用 `[内容, 类型, 说明, mi]` 四元组模式。
- `mi` 指向 `meanings` 的索引，多定义知识点时复用同一套渲染逻辑。

### 7.3 可直接复用的机制

| 英语已验证 | 数学复用 |
|---|---|
| 按词频排序 | 按考频/章节顺序排序（排序键可计算） |
| 音标派生文件 | 公式 LaTeX 预渲染 / 难度系数独立文件 |
| 词素高亮（标红） | 公式中关键步骤高亮（同构：找子串标红） |
| 双拨盘（主题/条目） | 双拨盘（知识点/例题）——UI 组件可直接复用 |
| 白队检查清单 | 建 `docs/white-checklist-math.md`，首版就包含"公式渲染对齐"检查 |
| 红蓝对抗流程 | 例题答案必须红队验算，蓝队修错题 |

### 7.4 数学特有的新增校验项

- 公式 LaTeX 语法校验（括号配对、命令存在性）。
- 例题答案可验算性：每道例题必须有"答案"字段，红队抽查验算。
- 知识点引用完整性：例题引用的知识点 id 必须存在（外键检查）。
- 难度标注一致性：同一知识点的例题难度应递增。

## 8. 一句话总结

**数据与表现分离、派生与源分离、校验先于审计、分批独立推送——这四条在任何学科都成立。**
